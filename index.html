JarBees

Local AI · Cognitive Architecture · Full-Stack Engineering IA Local · Arquitectura Cognitiva · Ingeniería Full-Stack

Development of a local-first AI architecture that integrates local language models, hybrid knowledge retrieval (RAG), persistent episodic memory, deterministic tools, and human-in-the-loop supervision mechanisms. Desarrollo de una arquitectura de IA local que integra modelos de lenguaje locales, recuperación híbrida de conocimiento (RAG), memoria episódica persistente, herramientas deterministas y mecanismos de supervisión humana.

Evolution: Evolución: 1. Full-Stack Origin 1. Origen Full-Stack → 2. Local LLM & RAG 2. IA Local y RAG → 3. Memory & Orchestration 3. Memoria y Orquestación → 4. Supervised Evaluation 4. Evaluación Supervisada → 5. Lab Integration 5. Integración con Lab
Contributions: Modular backend architecture, vector & relational RAG pipeline, persistent memory verification, context orchestration, evaluation workflows, voice pipeline, and interactive 3D web interface. Contribuciones: Arquitectura backend modular, sistema RAG vectorial y relacional, verificación de memoria persistente, orquestación de contexto, evaluación comparativa, pipeline de voz e interfaz web 3D.
Technologies: TypeScript, NestJS, PostgreSQL, pgvector, Prisma, Python, Local LLMs (Ollama / llama.cpp), Next.js, and Three.js. Tecnologías: TypeScript, NestJS, PostgreSQL, pgvector, Prisma, Python, LLMs locales (Ollama / llama.cpp), Next.js y Three.js.
Status: Active development. Core retrieval, memory, voice, and UI layers are functional; advanced execution remains human-supervised and depends on local GPU infrastructure. Estado: En evolución activa. Las capas de recuperación, memoria, voz e interfaz son funcionales; la ejecución avanzada permanece bajo supervisión humana y depende de infraestructura GPU local.
Technical Summary — Working · Built · Exploratory Scope Resumen Técnico — Qué funciona · Qué desarrollé · En exploración
1. What is working: Semantic and relational knowledge retrieval (`pgvector` + entity graph), episodic memory classification with database provenance checks, local GPU inference with speech-to-text/text-to-speech, and a Next.js web interface with a rigged 3D avatar. 1. Qué está funcionando: Recuperación semántica y relacional de conocimiento (`pgvector` + grafo de entidades), memoria episódica con verificación de procedencia en base de datos, inferencia en GPU local con voz bidireccional e interfaz web en Next.js con avatar 3D interactivo.
2. What I built: Evolved the project from an initial full-stack CRUD application (`productos_crud_bkd` / `productos_crud_frd`) into a multi-module cognitive backend with controlled evaluation states, transactional rollback, and human authorization gates. 2. Qué desarrollé concretamente: Evolucioné el sistema desde una aplicación full-stack inicial (`productos_crud_bkd` / `productos_crud_frd`) hacia un backend cognitivo modular con estados de evaluación controlada, reversión transaccional y compuertas de autorización humana.
3. Exploratory / Limitations: Full model inference and database retrieval run on local workstation hardware; the public GitHub Pages demo showcases the web interface and 3D avatar. Multi-step execution is intentionally gated by human approval rather than operating as an unconstrained autonomous agent. 3. En exploración / Limitaciones: La inferencia completa y la base de datos operan sobre hardware local; la demo pública en GitHub Pages muestra la interfaz web y el avatar 3D. La ejecución multi-paso está deliberadamente sujeta a supervisión humana en lugar de operar con autonomía irrestricta.

NIGHTMARE — DevilutionX WASM

C++ · Emscripten · WebAssembly · SDL2 · Browser Persistence C++ · Emscripten · WebAssembly · SDL2 · Persistencia en Navegador

Technical adaptation and WebAssembly compilation of the open-source DevilutionX engine (C++/SDL2 reconstruction of Diablo I) to execute natively inside modern web browsers with hardware-accelerated WebGL rendering, local asset management, and persistent savegame storage. Adaptación técnica y compilación a WebAssembly del motor open-source DevilutionX (reconstrucción en C++/SDL2 de Diablo I) para ejecutarse directamente en navegadores modernos con aceleración WebGL, gestión de archivos en cliente y persistencia local de partidas.

Contributions (vs. inherited engine): While the core C++/SDL2 game engine comes from the upstream DevilutionX project, I built the Emscripten/WASM web compilation pipeline, asynchronous virtual filesystem synchronization (IndexedDB), browser asset manager, and custom expansion/restoration design specifications. Contribuciones (frente al motor heredado): Mientras el motor C++/SDL2 base proviene del proyecto DevilutionX, desarrollé el pipeline de compilación web con Emscripten/WASM, la sincronización del sistema de archivos virtual en IndexedDB, el gestor de recursos en navegador y las especificaciones de restauración y expansión.
Technologies: C++, Emscripten, WebAssembly (WASM), SDL2, WebGL / OpenGL ES 2.0, IndexedDB, and JavaScript. Tecnologías: C++, Emscripten, WebAssembly (WASM), SDL2, WebGL / OpenGL ES 2.0, IndexedDB y JavaScript.
Status: Functional browser build deployed on GitHub Pages. Custom content expansion modules (Restoration Layer / Tristram Invasion) are documented as architectural designs in progress. Estado: Build funcional en navegador desplegado en GitHub Pages. Los módulos de expansión de contenido (Restoration Layer / Tristram Invasion) se encuentran en etapa de especificación y desarrollo incremental.
Technical Summary — Working · Built · Exploratory Scope Resumen Técnico — Qué funciona · Qué desarrollé · En exploración
1. What is working: Native C++ engine running in browser via WebAssembly and WebGL, client-side MPQ loader (supporting shareware demo or user-supplied retail data), and persistent savegame/configuration storage in IndexedDB. 1. Qué está funcionando: Ejecución del motor C++ en navegador vía WebAssembly y WebGL, cargador de archivos MPQ en cliente (compatible con versión shareware o datos provistos por el usuario) y guardado persistente en IndexedDB.
2. What I built: WebAssembly packaging workflow, browser storage persistence bridge, touch/gamepad web integration, cross-save compatibility handling, and technical expansion specifications. 2. Qué desarrollé concretamente: Flujo de empaquetado WebAssembly, puente de persistencia en almacenamiento del navegador, adaptación de controles web/táctiles, compatibilidad de partidas y especificaciones de expansión.

JarBees Scientific Lab

Physical Computing · Sensor Telemetry · Real-Time Visualization · Three.js Physical Computing · Telemetría de Sensores · Visualización en Tiempo Real · Three.js

Experimental instrumentation workspace that uses an Android mobile device as a physical sensor node to acquire, visualize, and record 3-axis geomagnetic and inertial telemetry in real time. Entorno experimental de instrumentación que utiliza un dispositivo móvil Android como nodo físico de sensores para adquirir, visualizar y registrar telemetría geomagnética e inercial triaxial en tiempo real.

Technical Details — Working · Built · Exploratory Scope Detalles Técnicos — Qué funciona · Qué desarrollé · En exploración
1. What is working: Real-time sensor acquisition bridges (via USB/ADB, Phyphox telemetry, and Web Sensor APIs), low-latency WebSocket streaming, 3D magnetic induction vector and 4-channel oscilloscope visualization with Earth-field tare calibration, and timestamped CSV logging tagged by experimental hypothesis. 1. Qué está funcionando: Puentes de adquisición de sensores en tiempo real (vía USB/ADB, telemetría Phyphox y Web Sensor APIs), streaming por WebSockets, visualización 3D del vector magnético y osciloscopio de 4 canales con tara de campo terrestre, y exportación de series CSV etiquetadas por hipótesis.
2. What I built: Node.js and Python sensor acquisition bridges, WebSocket telemetry server with sampling frequency/jitter metrics, and the Three.js + HTML5 Canvas diagnostic interface. 2. Qué desarrollé concretamente: Puentes de adquisición en Node.js y Python, servidor de telemetría WebSocket con cálculo de frecuencia efectiva y jitter, e interfaz de diagnóstico en Three.js y Canvas 2D.
3. Exploratory / Boundaries: Based on consumer mobile MEMS sensors suited for near-field trend detection rather than certified metrology. Automated LLM dataset interpretation and acoustic/resonance studies remain future research lines. 3. En exploración / Límites: Basado en sensores MEMS móviles de consumo orientados a detección de tendencias de campo cercano y no a metrología certificada. La interpretación automática por IA y los estudios de resonancia permanecen como líneas futuras.
